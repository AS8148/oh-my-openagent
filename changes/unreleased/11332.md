### Added

- Set `OMO_BUNDLED_SKILLS_DIR` to an absolute directory to share bundled skills
  across runtime installations. Absent or empty is unchanged. An invalid
  `OMO_BUNDLED_SKILLS_DIR` (relative, missing, not a directory, unreadable) now
  logs ONE error naming the variable and falls back to the plugin-relative
  bundled skills (lead ruling); task tools and the bare skill commands stay
  registered. Conditional, user, project, and memory skill roots keep their
  existing locations.
- An explicit `skillsDir` option now wins over a valid
  `OMO_BUNDLED_SKILLS_DIR`; precedence is explicit option, then a valid
  override, then the plugin default.
- The override resolver lives in the bundled-skills component itself (no
  separate module), which keeps the built `omo.js` inside its size budget:
  the change costs 531 bytes instead of 1,899.

## 2026-10-25 - Optional shared bundled skills directory (#11332)

Every bundled skill consumer (resources discovery, the task skill loader, and
the bare skill commands) uses one resolver for `OMO_BUNDLED_SKILLS_DIR`. The
override replaces only `plugin/skills`; `plugin/skills-conditional` remains
relative to the plugin. Absent or empty is unchanged. An invalid
`OMO_BUNDLED_SKILLS_DIR` (relative, missing, not a directory, unreadable) now
logs ONE error naming the variable and falls back to the plugin-relative
bundled skills (lead ruling), plus one session notice; the report is once per
process across both extension bundles. An explicit `skillsDir`
option wins over a valid override.
