**Synced memory refuses a forged or reordered history on the device, the same way the server does.** memory-core now checks every sync object, the hash chain linking them, and the device keyring folded from it, using the format the service ships. A device rejects a record signed by a key that was rotated out or revoked, a dropped or reordered entry, a recovery join from a removed recovery key, and a batch sealed for another account. It treats the server as untrusted: a device trusts an account history only if it starts from the root it pinned during its own pairing or recovery, so a history the server invents, or a different root that looks valid, is refused before any key is opened. A key wrap opens only from a record of that trusted history, and only through the device's own keyring. A missing or damaged pin is treated as no trust at all, and the device asks to re-pair or recover. A replayed batch, a swapped record body, an unsigned row in a vetoed epoch and a row with fields the format does not define are each refused and counted. Nothing syncs to a server yet.
