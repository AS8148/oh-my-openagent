**Memory patches that move a file twice in one change no longer leave the memory repository blocked.** A chained move such as `a.md -> c.md -> d.md` listed the intermediate `c.md` as a path to commit even though it never existed, so git refused the commit and the next memory write found a dirty tree. The intermediate is now dropped when it never existed and kept when it was a real tracked file. Thanks to @MoerAI for the fix.
