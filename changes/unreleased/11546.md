**Opening a session no longer hangs on a Mac whose `/home` automounter is stuck.** With a home folder outside `/Users` (the desktop app's own home, QA or custom homes), the telemetry check resolved `/home`. When macOS's `auto_home` automounter stopped answering, that call never returned: the engine stopped responding and every request timed out. The check, and every place that resolves a path a tool or the model hands in, now treats `/home` and `/net` as plain text on macOS. ## 2026-10-28 - Never resolve a macOS automount trigger on the host loop (#11546)

`@oh-my-opencode/utils/path-containment` gains `isDarwinAutomountTriggerPath(path, { platform, homeDir })`. It is true only on darwin, for `/home`, `/net` and anything below them, and never for the user's own home subtree. It is decided from the string alone, before any syscall. `telemetry/omo-native-session.ts` `isInsideTempDir` compares trigger candidates (and a HOME whose parent is one) lexically. The class sweep applies the same rule to `skill_loaded` (`omo-native-tools.ts`), the memory read classifier, the memory guard and policy guard roots, kibitzer `resolveWorkspacePath`, project memory read grants and sandbox `canonicalPath`. `automount-trap.test-support.ts` forces darwin and traps every resolving fs entry, so each site's table test fails if it ever resolves a trigger.
