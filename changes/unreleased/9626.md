**A store extension's `orderBy` can only name columns its statement returns, and its text never reaches the SQL.** `orderBy` used to be pasted into the gateway's ordered read as given, so a `LIMIT`, an `OFFSET` or a column the statement does not select failed as broken SQL (`near "LIMIT": syntax error`, `no such column`). Each comma-separated term must now be one of the statement's own output columns (matched case-insensitively, as SQLite does), optionally with `COLLATE BINARY`/`NOCASE`/`RTRIM`, `ASC`/`DESC` and `NULLS FIRST`/`NULLS LAST`. The ORDER BY is rebuilt from the matched column name and those fixed keywords. Anything else, including quoted or bracketed names, comments, look-alike Unicode letters and unknown columns, is refused with `extension_schema_violation` and a message that names the rule and the columns the statement does return; put a `LIMIT` in the statement itself.
