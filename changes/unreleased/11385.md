**Cancelling or amending a DAG run now stops every child the run owns, and an amended node never adopts its old child.** A completed node's child that resumed on its own (its background work woke it) kept running after the run was cancelled, because cancel stopped only the children it was still attached to. When the run was then amended to change that node, re-admission attached the old live child as the new attempt, so the amended model, category and prompt never ran while the old child kept writing in the node's worktree. Cancel now stops every live child owned by the run. Before a re-entered run admits anything, a live child of an earlier attempt of a node about to run again (an amend or retry raised its attempt) is cancelled, so the new attempt starts fresh. If that child cannot be stopped, the node fails with the retryable `stale_attempt_alive` instead of being attached or run beside a second child. A live child of the same attempt is still adopted as before (#7412).
