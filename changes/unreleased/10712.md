**Thread controls authenticate RPC hosts and attach the selected session before making changes.** Mutations carry the selected session's durable identity, so a replacement host cannot silently redirect them to a different session that reused its routing id. New hosts use challenge-response and connection-local attachments; older hosts retain their existing requests. Raw task-host warm requests use the same authentication exchange. ([#10712](https://github.com/code-yeongyu/oh-my-openagent/pull/10712))

## 2026-10-20 - Authenticate RPC hosts and attach the selected thread before mutation (#10712)

The thread and gateway socket client negotiates the endpoint's protocol on each
short connection, proves the endpoint key with the canonical challenge-response,
and attaches using the selected thread's routing and durable ids before changing
it. Interrupt, rename, model, reasoning, wake, release and UI answers release that
attachment before closing. A newly created thread is named on its opening
connection. Caller-aware release preserves the refusal for other attached clients
unless forced. Hosts without attachment capabilities retain their existing
requests; terminal control sockets retain their raw-secret handshake.

Mutation ports, lazy forwarding and gateway endpoint references carry the
selected durable id rather than recovering it from a later routing-id lookup.
The key-root option and SENPI_RPC_KEY_ROOT select credentials only, without
changing the caller's profile.

Attachment outcomes follow wire contract v1.1. A draining host's attach refusal
(session_busy_lifecycle with reason host_draining) surfaces as a transient
host_draining error, and a session_not_attached attach refusal as a typed
session_not_attached error; neither aborts or closes the session. Once a
mutation has taken effect its result is returned: a session_not_attached
release means the hold is already gone, and any other release failure is
logged once instead of failing the mutation.

## 2026-10-20 - Authenticate raw RPC host requests (#10712)

Raw askHost connections negotiate and complete the endpoint's challenge-response
before sending warm or liveness reads. The same small socket/authentication
module serves the thread client. It checks key-record ownership, modes, regular
file identity and the versioned key payload, verifies the server proof before
sending a client proof, and honors SENPI_RPC_KEY_ROOT independently of settings.
Missing records take the logged grace transition; unsafe records and wrong
proofs refuse without fallback. Windows pipe secrets and senpi RpcClient paths
remain owned by their existing transports.
