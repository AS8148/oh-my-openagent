**A process child whose provider has no usable sign-in now moves on to the next provider instead of failing.** When the engine refuses a child's first prompt with `provider_credentials_missing` or `provider_credentials_expired`, the task skips the remaining models on that provider and starts on the next provider in its fallback chain, ending on the parent session's model when nothing else is left. Each hop is recorded as a `task_model_fallback` event naming the provider. An engine that does not send these codes behaves exactly as before.
