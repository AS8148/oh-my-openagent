**A delegated task whose model is not served by its route fails instead of silently switching models.** When the provider answers that it does not serve the configured model (`model_not_found`, `unknown provider for model`, Anthropic's `not_found_error` naming the model, or Google's `models/<id> is not found`), the task ends in error with the provider's answer and a line naming the `categories.<name>` key to fix in omo.json; it is no longer relaunched on the next rung of its category chain, and it is never reported as an exhausted fallback chain. This includes OpenAI's `model_not_found` for a model the key may not use, which used to try the provider's other models. Stored task errors and task event logs redact credentials a provider echoes (keys, tokens, cookies, JWTs).
