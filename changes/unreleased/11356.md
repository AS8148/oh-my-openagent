**A delegated task whose model is not served by its route fails instead of silently switching models.** When the provider answers that it does not serve the configured model (`model_not_found`, OpenAI's "The model `<id>` does not exist", `unknown provider for model`, Anthropic's `not_found_error` naming the model, or Google's `models/<id> is not found`), the task ends in error with the provider's answer and a line naming the `categories.<name>` key to fix in omo.json; it is no longer relaunched on the next rung of its category chain, and it is never reported as an exhausted fallback chain. This includes OpenAI's `model_not_found` for a model the key may not use, which used to try the provider's other models. Provider text a task stores is redacted by value, with the same rules as senpi: the task's error, the parent-model fallback note (`parent_model_fallback.detail`) and the task event log never hold a key, token, cookie, password or JWT a provider echoed, whatever header, JSON, URL or form shape it came in.
