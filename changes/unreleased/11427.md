**A queued steer to a subagent keeps its own id across the child boundary, and a lost acknowledgment is checked before anything is sent again.** A message queued for a child that is still starting reaches it under the id it was queued with, so a drain repeated after a restart replays instead of delivering a second copy. When the child's acknowledgment is lost, omo asks the child whether it holds that id (`get_pending_inputs`): held settles it, not held resends the same id, and an unreadable answer keeps it uncertain instead of guessing.
