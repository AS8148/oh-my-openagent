**Gateway wakes, UI answers and releases reach a host session known only by its durable id.** A multi-session host refuses any command that names no session, so a wake for a session read from disk or found by `thread locate` was lost with `missing_session_id`. The client now looks the session up on its host by durable id and routes the command; when no live session holds it, the delivery stays queued for the session's next start and `omo thread report` says the completion's wake did not reach it. ([#11188](https://github.com/code-yeongyu/oh-my-openagent/pull/11188), fixes [#11185](https://github.com/code-yeongyu/oh-my-openagent/issues/11185), part of [#10995](https://github.com/code-yeongyu/oh-my-openagent/issues/10995))

**Turning telemetry off through an environment variable no longer deletes summaries another session queued under a profile.** A session whose `OMO_PROFILE` turns telemetry on could lose its queued usage summary when another session started with `DO_NOT_TRACK` and the base `omo.json` setting was off. Each summary queued from now on remembers the config it was recorded under and is judged by it when it is sent, resumed or cleaned up; summaries queued before the upgrade keep the old reading until they expire. ([#11198](https://github.com/code-yeongyu/oh-my-openagent/issues/11198)) ([#11202](https://github.com/code-yeongyu/oh-my-openagent/pull/11202))

**The telemetry reference now states exactly which queued summaries an opt-out deletes and what the legacy `rollups` cleanup can and cannot remove.** ([#11181](https://github.com/code-yeongyu/oh-my-openagent/pull/11181))

**senpi's on-demand memory report now shows OmO's task children and memory recall.** With `SENPI_MEMORY_REPORT=1`, a report gains an `omoTask` section (resident task children, cached task records and their bytes, open event logs) and an `omoRecall` section (loaded memory corpora, their text bytes, the recall index's term arrays and dictionary size), so a large session's memory can be traced to these layers. Nothing is measured unless a report is taken. ([#11178](https://github.com/code-yeongyu/oh-my-openagent/pull/11178), part of [#9442](https://github.com/code-yeongyu/oh-my-openagent/issues/9442))

**Kimi K3.1 gets its own Sisyphus, Sisyphus-Junior and Atlas prompts.** Kimi K3.1 Pro ids (`k3.1-pro`, `kimi-k3.1-pro` and their Highspeed versions) now route to separate copies of the K3 prompts instead of sharing K3's, and the Kimi Code id `k3.1-pro` gets a Kimi prompt at all. `kimi-k3.1-pro` maps to Kimi Code's `k3.1-pro` id. ([#11197](https://github.com/code-yeongyu/oh-my-openagent/pull/11197))

**Protocol-2 account storage has separate credential and pending-revocation namespaces.** Legacy credential writes and deletes cannot overwrite either namespace; the origin key and native storage-error mappings stay shared. This is storage support for the protocol-2 rollout, not enrollment activation. ([#11177](https://github.com/code-yeongyu/oh-my-openagent/pull/11177), refs [omo-service#628](https://github.com/sisyphuslabs/omo-service/issues/628))

**A background task whose task host stays unreachable no longer comes back as a leftover session after recovery gives up.** When a task child's reconnect timed out and its host answered only later, the stalled reconnect could retry after the session had already been closed and reopen it on the host, leaving a live session and its processes behind. The abandoned reconnect now stops retrying, while the parked child keeps its respawn and its single notice. ([#11246](https://github.com/code-yeongyu/oh-my-openagent/pull/11246), fixes [#10925](https://github.com/code-yeongyu/oh-my-openagent/issues/10925))

**Windows Codex commands no longer stop at a command syntax error.** Generated command shims accept a quoted `NODE_REPL_NODE_PATH` in `config.toml` and also run when that setting or the config file is absent. Thanks to @fvegiard for the report and @LilMGenius for the fix. ([#11222](https://github.com/code-yeongyu/oh-my-openagent/pull/11222), fixes [#7473](https://github.com/code-yeongyu/oh-my-openagent/issues/7473))

### Fixed

Before, a child started without an explicit environment got the values the process started with, so it could run with an out-of-date temp or home directory.
