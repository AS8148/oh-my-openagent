**A workflow node whose child resumes on its own now follows that child's resumed run.** A node whose child finished its turn and then woke up again (its background job or monitor fired) stayed `completed` even when the resumed run failed, so the run summary counted it as completed ("5 completed, 0 failed"). The node now goes back to running when its child resumes and takes the resumed run's outcome: a failure marks the node failed, the run summary counts it, and dependents that had not started yet are skipped. Dependents that already started on the earlier completion keep their own result. ([#11386](https://github.com/code-yeongyu/oh-my-openagent/pull/11386), part of [#10487](https://github.com/code-yeongyu/oh-my-openagent/issues/10487))

## 2026-10-26 - A DAG node re-watches its task after task_self_resumed (#11386, part of #10487)

`reopenSelfResumedTurn` moved a settled task back to `running` under the next run epoch, but the
DAG scheduler had already dropped the node's attachment when it folded the first outcome, and the
only path that re-watched a finished node was an explicit `send` revival. A resumed run's later
error therefore never reached the node, the run summary, or the parent's wake.

`TaskManager.subscribeSelfResumed(taskId, listener)` (optional on the contract; the concrete
manager implements it through `createSelfResumedListeners` in `manager/self-resumed-turn.ts`)
announces a reopen after the record is back to `running`. When the scheduler folds a `completed`
outcome it subscribes for that node's task; on the announcement, while the run is still `running`
and the node is still `completed` with that task, it journals `completed -> running` (reason
`resumed`) and re-attaches the task to the settle loop, which folds the resumed run's outcome
like any other. Dependents already admitted keep their outcome; pending dependents wait for the
node again and are skipped by the quiescent cascade if it fails. Watches are disposed when the
run settles or the scheduler is suspended: a terminal run stays settled evidence (#7412), and the
task's own resumed-turn notification still reaches the parent.

Tests: `dag/scheduler.test.ts` (real scheduler + fake manager) covers the incident shape (node A
completed, B admitted, A resumes and errors: A failed, run failed with 1 completed / 1 failed) and
a pending dependent skipped after the re-opened node fails; `manager/manager-self-resumed-turn.test.ts`
asserts the announcement fires after the reopen and not for a cancelled task.
