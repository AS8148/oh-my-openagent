**Error messages name a step that works today.** While terminal sign-in is closed, every "run omo login" hint (sign-in, `omo sync`, expired or unreadable sign-ins, memory sync) points at the OmO desktop app instead, and keeps naming `omo login` once accounts open. A refused service request says whether to sign in again, wait, try later or update omo, instead of always blaming sign-in. A missing plugin file, `omo thread` and `omo update` on a broken current install print the exact reinstall command, and `/computer` says why computer use is unavailable. ## 2026-10-26 - Reinstall and sign-in guidance (#11390)

The launcher sets `OMO_REINSTALL_COMMAND` (`updateTarget().command`) for the engine so the plugin can name the reinstall command after `SENPI_BRAND` is scrubbed. `runThreadCommand` takes a `reinstall` step from its caller (npm: the reinstall command; compiled: the releases page). `omo update` on an install already at the channel version whose engine tree cannot be resolved exits 1 with the reinstall command. `omo sync`'s account read maps its HTTP status through the shared refusal guidance.
