## 2026-10-28 - Memory shutdown waits for in-flight cache reads (#11671)

`MemoryBlockCache.settled()` and `RecallCorpusCache.settled()` now cover every call from its first repository read (HEAD, the persisted-store load, the compile or corpus load), through a shared `InFlightReads` tracker; the prompt prebuild runs its HEAD read through `MemoryBlockCache.track()`. Before, a read with no persisted store, or one still reading HEAD, was invisible to `settled()`, so the shutdown drain returned while `git ls-tree` still ran inside the identity directory.
