**A category or agent model change in omo.json applies to the next delegated task without restarting the session, and a broken omo.json stops the spawn instead of switching models.** The task engine reads omo.json once at every spawn, so an edited category chain or agent reaches the next child even while other children run and `/reload` is held. When any existing omo.json layer cannot be parsed, read or validated, that spawn fails with an error naming the file and the position (`line:column`, or the JSON path of the invalid value); it never routes on another layer, the built-in defaults or the session's startup config. Still read once at session start: the `task` settings (state dir, runners, residency), the plan-gate and DAG spawn policy, and the agent list in the task tool's description.
