**A category or agent model change in omo.json applies to the next delegated task without restarting the session, and a broken omo.json stops the spawn instead of switching models.** The task engine reads omo.json once at every spawn, so an edited category chain or agent reaches the next child even while other children run and `/reload` is held. When an existing omo.json layer cannot be parsed or read, or any field that decides which model a child runs on is invalid in the base config, its `[native]`/`[senpi]` block, the active profile or that profile's block (a category's or agent's `model`, `models`, `fallback_models` or reasoning selectors, `exclude_models`, a model catalog cycle; a wrong type, `null`, or a model id that is neither `provider/model` (the legacy `model (high)` and `model high` suffixes still count) nor a catalog name any of those scopes defines), that spawn fails with an error naming the file and the position (`line:column`, or the JSON path of the field). It never routes on the rest of the file, another layer, the built-in defaults or the session's startup config. An invalid field that does not route a Senpi child (for example `task.default_concurrency`, a `[codex]` block, or a profile that is not active) is dropped with a warning, as before. Still read once at session start: the `task` settings (state dir, runners, residency), the plan-gate and DAG spawn policy, and the agent list in the task tool's description.
