### Fixed

- Memory sync's CLI account source reads the OS credential store authoritatively under the shared per-origin credential lock, so a read that began before another process replaced the credentials can no longer authorize a signature, a service mutation or a trust-pin rename. A legacy credential gets a concrete generation before any token or identity request, and identity resolution must name both the account and the unrevoked current device (#11750).
- Memory sync can use a desktop app's main-owned account over its private channel: engine-side ports, a lock-held pin boundary over main's durable generation record, and a genesis bridge bound to each operation's handle. A desktop-launched engine selects that source once in its main thread and hands each session Worker the outcome on its own port; it never falls back to the CLI credential source (#11750).
